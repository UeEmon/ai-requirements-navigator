# コーディング・テスト工程への引き継ぎ

要件定義の成果物を、開発とテストの担当者に渡すための機能です。画面では「テスト・引き継ぎ」タブにまとまっています。設計判断は [ADR 0009](adr/0009-handoff-to-coding-and-test.md) にあります。

## 何が渡るか

| 後工程で必要なもの | 成果物 | 作り方 |
| --- | --- | --- |
| 何を作るか | EARS の要件文（機能・非機能）、優先度、根拠、版 | ヒアリング・資料分析・非機能要件シート |
| 品質の目標 | 非機能要件シート（26項目の水準と理由） | 非機能要件 |
| 業務の流れ・振る舞い | ユースケース・シーケンス・状態遷移・アクティビティ図、業務フロー（現状・見直し後） | UML・資料分析 |
| データ | **データ項目定義**（エンティティ・項目・コード上の名前・型・キー・必須・桁や形式・区分値） | 設計モデル（UML） |
| 誰が何をできるか | **権限表**（役割 × エンティティの CRUD） | 設計モデル（UML） |
| 外部とのやり取り | **外部とのやり取りの一覧**（相手・方向・方式・タイミング・データ） | 設計モデル（UML） |
| 画面 | 画面一覧・画面遷移図・ワイヤーフレーム（見た目は持たない） | 画面 |
| 作業 | エピック・ストーリー・タスク、受け入れ条件、見積り | 実装連携 |
| **テスト** | **要件ごとのテストケース**、非機能要件の確認方法、受け入れテスト、要件 → テストの追跡 | 要件から規則で作成 |
| 未決事項 | **着手前チェック**と未決事項の一覧 | 規則で点検 |

太字が、この機能で加わったものです。

## テストケースの作り方

EARS の文型ごとに、確かめる観点を決めています。AI は使わないので、同じ要件からは同じテストケース（同じ ID）が作られます。要件を直すと自動で作り直されます。

| 文型 | 作るケース |
| --- | --- |
| 普遍（〜は、〜しなければならない） | 正常系 |
| イベント駆動（〜とき、…） | 起きたとき（正常系）／条件を満たさないとき（誤って実行されない） |
| 状態駆動（〜間、…） | 状態の内／状態の外 |
| 望ましくない振る舞い（〜場合、…） | 異常系（異常を再現する手段を用意する） |
| オプション（〜がある場合、…） | 機能あり／機能なし |
| 複合（〜間に〜とき、…） | 状態の内で起きたとき／状態の外で起きたとき |
| 数値と単位を含む文（3秒、100件、99% など） | 境界値（ちょうど・超える・下回る） |

- テストの ID は `TC-<要件ID>-<番号>`（受け入れテストは `AT-<ストーリー>-<番号>`）
- 非機能要件は、非機能要件シートの項目ごとに決めた確認方法（例：応答時間 → 性能試験、復旧までの時間 → 復旧訓練、データを戻せる時点 → リストア試験、弱点への対応 → 脆弱性診断）を付けます。シートから作っていない非機能要件は文の言葉から推定し、推定したことを表示します
- 具体的なテストデータと手順は、テスト設計の工程で決めます

## 着手前チェック

次の点を点検し、「引き渡せる／確認事項を共有すれば着手できる／足りないものがある」を判定します。△・× の項目には、直す画面へのボタンが付きます。

- 要件：機能要件がある、EARS の検査を通る、未決事項がない、非機能要件をすべて検討した
- 設計の材料：設計モデルがある、データ項目定義がそろっている（主キー・区分値）、権限表がある（役割が複数のとき）、外部とのやり取りが整理されている（連携・メール・取り込みなどを含む要件があるとき）、画面一覧が機能要件をカバーしている
- テスト：タスク分解が要件をカバーしている、すべての要件にテストケースがある、機能要件に受け入れテストがある、非機能要件の確認方法が決まっている
- 管理：確定版がある、判断待ちの変更要求がない、要件の変更が画面・タスクに反映されている

未決事項には、ヒアリングで確認できていない観点、保留中の非機能要件（決める人）、反映していない画面への意見が並びます。

## 出力

| 出力 | API | 用途 |
| --- | --- | --- |
| テストケース（CSV、BOM 付き UTF-8） | `GET /api/projects/:id/tests.csv` | テスト管理ツール・表計算ソフトに取り込む |
| 引き継ぎパッケージ（JSON） | `GET /api/projects/:id/handoff.json` | 開発者のツール・AI コーディングツールに渡す |
| 仕様書の 14〜18 章 | `GET /api/projects/:id/spec.(md\|docx\|pdf)` | データ設計・権限表・外部とのやり取り・テスト仕様・着手前チェック |

引き継ぎパッケージの形（`format: "arn-handoff/1"`）：

```text
project / baseline / howToUse
requirements[]   code, type, title（EARS の文）, ears（構造）, priority, source, version, nfrKey
nfr              profile, items[]（key, status, level, rationale, verification）
design           model（設計モデル）, tables（entities, data, crud, interfaces）
screens          画面一覧（画面・要素・遷移・対応する要件）
tasks            エピック・ストーリー・タスク・受け入れ条件
tests            cases[], trace[], coverage
readiness        verdict, score, checks[], openQuestions[]
```

## 対象外（設計工程で決めるもの）

物理 DB 設計（テーブル定義）、API の詳細仕様（OpenAPI）、画面のレイアウトと文言、テストデータとテスト環境の詳細。
