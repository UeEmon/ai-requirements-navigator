# 画面イメージと、確定後の変更管理

## 画面イメージ（ワイヤーフレーム）

確定した機能要件から、AIが **画面の一覧と画面のつながり** を作ります。「画面」タブでは、ボタンを押すと次の画面に移るワイヤーフレームを確認できます。HTMLファイルとして保存して関係者に見せることもできます。

### 細部にこだわらないための工夫

要件定義の段階で画面の見た目を詰め始めると、時間がかかるうえに、本来確認すべき「必要な情報と操作」から注意がそれます。そのため、次のようにしています。

| 工夫 | 内容 |
| --- | --- |
| 見た目を表現できない | 画面モデルには、目的・使う人・対応する要件・表示する情報と操作・遷移先しか持たせていません。AIが色や寸法を出しても捨てます |
| 完成品に見えない | 白黒・手書き風のワイヤーフレームにし、「イメージ」の透かしと「見た目は設計工程で決めます」という説明を常に表示します |
| 意見の振り分け | 画面への意見を「要件に関わるもの（足りない項目・できない操作・画面のつながり）」と「見た目の細部（色・大きさ・配置・装飾など）」に自動で振り分けます。細部は **設計工程への申し送り** として記録し、作り直しには使いません |
| 作り直しの目安 | 3回以上作り直すと、要件の確認に戻るよう促します |
| 仕様書への反映 | 仕様書には画面一覧・画面遷移図と、申し送りの一覧が入ります。見た目の要望は失われず、設計工程に引き継がれます |

要件に関わる意見で、新しい要件が必要なもの（例：「予約を検索したい」）は、ヒアリング、または確定後なら変更要求で要件として確定してください。画面の作り直しだけでは要件は増えません。

## 要件定義の確定と変更管理

「変更管理」タブで **要件定義を確定** すると、その時点の要件を確定版（v1）として保存します。確定後は次のようになります。

- 要件一覧での直接の編集・削除はできません（「変更要求」ボタンから登録します）
- ヒアリングで採用した案は、要件に直接加えず「追加」の変更要求になります

### 変更要求の流れ

1. **登録**：種類（変更・追加・削除）、対象の要件、変更後の内容、理由を入力します
2. **影響分析**：次の2つを組み合わせて、後の工程への影響を示します
   - **トレース（機械的）**：変更する要件から、画面・実装タスク（ストーリー）・登録済みの課題をたどります
   - **AIによる分析**：関連する要件、設計（UML）の要素、画面、ストーリー、追加の工数の目安、リスク、代替案。複数AIモードでは生成AIすべてで分析し、何台が同じ指摘をしたか（例：AI 2/2）を表示します
3. **判断**：結果を見て、次から選びます。どれを選んだか、理由、判断した人は記録に残ります

| 選択肢 | 結果 |
| --- | --- |
| 要件定義を変更する（追加する／削除する） | 要件を変更し、確定版の版を上げます（v2、v3…）。見直しが必要な設計・画面・ストーリー・課題の一覧を表示します |
| 代替案で対応する | AIが示した、要件を変えずに目的を果たす案や影響の小さい案の内容で変更します |
| 保留する | 今の要件定義のまま進めます。変更要求は残り、後から分析し直して判断できます |
| 変更しない | 理由を記録して終了します |

変更した後は、画面・実装タスクの分解結果に「要件が変わっています」と表示されるので、必要に応じて作り直してください。登録済みの課題は自動では更新しません（影響分析の一覧から課題を開いて更新します）。

仕様書には、確定版の番号と変更履歴（変更要求ごとの判断）が入ります。

## API

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/projects/:id/screens` | 最新の画面一覧・意見（反映待ち／反映済み／申し送り）・作り直しの促し |
| POST | `/api/projects/:id/screens/generate[?async=1]` | 画面の作成・作り直し（`applyFeedback`：反映待ちの意見を使うか） |
| GET | `/api/projects/:id/screens/prototype.html[?download=1]` | ワイヤーフレーム（スクリプトなしのHTML） |
| POST | `/api/projects/:id/screens/feedback` | 画面への意見 `{ screenKey?, text }`。振り分けの結果と説明を返す |
| GET / POST | `/api/projects/:id/baseline` | 確定版の状態・確定 |
| GET / POST | `/api/projects/:id/changes` | 変更要求の一覧・登録 |
| POST | `/api/changes/:id/analyze[?async=1]` | 影響分析 |
| POST | `/api/changes/:id/decide` | 判断 `{ option: apply / alternative / defer / reject, reason, alternativeIndex? }` |
