# ADR 0007: 資料からの要件は「業務の見直し」を経て作り、要件文は EARS の構造で持つ

- 状態: 決定
- 日付: 2026-10-02

## 背景

- 議事録や既存システムの資料から要件を抜き出すと、今のシステムの画面・帳票・機能をなぞった「焼き増し」になりやすい
- AIは資料にない課題をもっともらしく書くことがある
- 要件の文は、書く人やAIによって表現がばらつき、解釈が分かれる

## 決定

- 分析は「現状のフロー → 課題（資料の引用つき）→ 見直し案（ECRS を先に）→ 見直し後のフロー → 引き継がないもの → 要件案」の順に出力させ、要件案は見直し後の業務と見直し案に結び付ける
- 引用が資料に実在するかは、AIではなくシステムが文字列で照合する（空白・かぎ括弧の違いは無視）
- 見直し率・根拠の確認率・ECRS の案の数・EARS の合格率を計算し、焼き増しや推測の疑いを警告する。採否は利用者が決める
- 複数AIモードでは、UMLと同じく匿名で比較し、合計点はシステムが計算する
- 資料はファイルではなく本文のテキストだけを保存する。Word は自前で読み（依存を増やさない）、PDF は pdfjs-dist（Apache-2.0）を使う
- 機能要件・非機能要件は EARS の構造（型・きっかけ・状態・機能・主語・応答）で保存し、文はシステムが組み立てる。文の検査は規則で行う

## 理由

- 焼き増しを防ぐには、要件を作る前に「その業務自体が必要か」を問う手順を強制するのが確実
- 根拠の照合を機械的に行えば、利用者は「資料で確認」された課題から判断できる
- 文を構造から組み立てれば、表現の振れが原理的に起きない。人が直接書いた文にも同じ検査をかけて、問題を示せる

## 影響

- 構造を持たない古い要件や、人が文で直接書いた要件は、検査の結果（警告）を表示する。強制的な書き換えはしない
- 画像だけのPDF（スキャン）は取り込めない（文字認識は行わない）
