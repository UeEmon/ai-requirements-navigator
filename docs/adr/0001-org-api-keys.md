# ADR 0001: AIのAPIキーは組織ごとに登録する

- 状態: 決定
- 日付: 2026-10-02

## 背景

Claude・GPT・Gemini を使うにはAPIキーが必要です。運営側でまとめて契約するか、利用する組織が自分のキーを登録するかを決める必要がありました。

## 決定

**組織ごとに、その組織の管理者（admin）が自分のAPIキーを登録する。**

- 登録・削除は admin 権限のみ。一覧表示は末尾4桁のみ
- 保存時に暗号化する。ローカルDockerでは `MASTER_KEY` による AES-256-GCM、AWSでは AWS KMS
- 暗号化の追加認証データ（AAD／KMSの暗号化コンテキスト）に組織IDを使い、別組織のレコードに付け替えても復号できないようにする
- 利用量（トークン数）は組織単位で記録し、管理者が確認できる
- モデル名も組織ごとに指定する（各社の最新モデルに合わせて組織側で更新できる）
- 登録後も、モデル名・表示名・接続先・APIキー・月間上限を管理者が変更できる。種類（ベンダー）は変更できない（変える場合は登録し直す）。APIキーを省略した変更では今のキーを使い続ける
- 費用の管理のため、組織全体と登録AIごとに月間トークン上限を設定できる
  - 組織の上限に達した場合: その月はAIを呼び出さない（HTTP 429）
  - AIごとの上限に達した場合: そのAIだけを外して続行する。評価AIが外れた場合は評価なしで案を表示する
  - 80% を超えたら警告を表示する
  - 上限は呼び出し前に判定するため、1回分だけ上限を少し超えることがある

## 理由

- 費用と利用規約の責任が、AIを使う組織に明確に帰属する
- 運営側が各社と一括契約・請求の仕組みを持たずに済む
- 組織ごとに使えるAI・モデルを選べる（社内規程で特定ベンダーのみ許可、など）

## 影響

- 初回利用時に、管理者がAPIキーを登録する手順が必要（画面「AI設定・プロジェクト」）
- 複数の組織で使うSaaSとしても、そのまま運用できる
