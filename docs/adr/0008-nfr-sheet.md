# ADR 0008: 非機能要件は固定の項目表で網羅し、確定前に検討の終了を確かめる

- 状態: 決定
- 日付: 2026-10-02

## 決定

- 非機能要件は会話だけに頼らず、7大項目・26項目の固定の表（シート）で検討する。IPA「非機能要求グレード」の考え方（段階的な水準、重要度に応じた推奨）を参考にし、文言は独自に作成する
- システムの性格を4つの質問で聞き、大項目ごとの重要度から推奨水準を決める
- 各項目は「決定／対象外（理由必須）／保留（決める人を記録）」のどれかにする。推奨より低い水準には理由を求める
- 項目どうしの矛盾は規則で検出する（AIに任せない）。結果が毎回同じで、理由を説明できるため
- 複数AIの提案は採否を自動で決めず、意見が分かれた項目を人が決める。一致した提案のみまとめて採用できる
- 要件定義の確定時に、未検討の項目と要対応の矛盾がないかを確かめ、残っていれば止める。理由を書けば確定でき、そのことを監査ログに残す
- 決めた水準から EARS の非機能要件を機械的に作る（ひな形）。体制の取り決めや「対策しない」は要件にしない

## 理由

- 非機能要件の抜けは稼働後に発覚しやすく、手戻りの費用が大きい。項目を固定して「検討したか」を見える化するのが確実
- 高すぎる水準は費用を押し上げるため、推奨と費用の目安を並べて、業務に見合った水準を選べるようにする
- 確定を完全に禁止すると現場の進め方に合わないため、理由を記録すれば先に進めるようにした
