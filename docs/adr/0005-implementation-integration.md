# ADR 0005: 実装工程への連携は「分解結果の保存＋冪等な登録」で行う

- 状態: 決定
- 日付: 2026-10-02

## 決定

- 要件からのタスク分解は、エピック → ストーリー → 作業タスクの3段階に固定する。キー（`E1-S2` など）はAIではなくシステムが振る
- 各ストーリーは元になった要件コードを持ち、存在しないコードは取り除く。機能要件・非機能要件のうち、どのストーリーにも対応しないものを警告する
- 分解結果（`task_plans`）と、外部ツールへの登録結果（`task_exports`：キー → 課題URL）を別々に保存する。登録は「同じ分解結果・同じ連携先で登録済みのキーは飛ばす」ため、何度実行しても重複しない
- 外部ツールとの通信は SDK を使わず、各ツールの REST API を `fetch` で直接呼ぶ（GitHub REST v3、Jira REST v2、Backlog API v2）
- 連携先のトークンは AI の APIキーと同じ `KeyEncryptor` で暗号化する
- 作業タスクは外部ツールの子課題にせず、ストーリーの本文のチェックリストにする

## 理由

- 外部APIの失敗（レート制限・権限・一時障害）は避けられないため、失敗した分だけをやり直せることを優先した
- SDK を加えないことで、依存とライセンスの確認対象を増やさない（OSS方針）。必要なAPIは課題の作成と参照のみ
- 子課題の扱い（サブタスクの種類、親子課題の有効化）はツールと設定によって異なり、失敗しやすい。チェックリストならどのツールでも同じように扱える
- AIの出力するキーに依存すると、分解し直したときにトレーサビリティが崩れる

## 影響

- 分解し直すと新しい分解結果になり、トレーサビリティは最新の分解結果で表示する。以前の登録結果は以前の分解結果に残る
- 外部ツール側で課題を削除・移動しても、こちらの記録は更新されない（登録時点の対応を示す）
