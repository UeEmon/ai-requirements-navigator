# ADR 0013: プロンプトのキャッシュでトークンの消費を抑える

- 状態: 決定
- 日付: 2026-10-20

## 背景

要件ナビは、ヒアリングの回答のたびに、生成AI（1〜複数）と評価AIへ「指示（system）・プロジェクトの前提・確定済みの要件・回答」を毎回すべて送っていた。指示とプロジェクトの前提は、同じプロジェクトで続けて呼ぶ間ほとんど変わらないのに、毎回通常の料金で入力トークンとして数えられていた。各社の AI には、先頭から同じ部分を使い回す「プロンプトのキャッシュ」があり、キャッシュから読んだ入力は通常の 1〜5割程度の料金になる（Claude は約1割、ChatGPT・Gemini は 1〜5割。モデルによる）。ただし、使い回せるのは「先頭から1文字も違わない部分」だけで、変わる部分が前にあると、その後ろはすべて使い回せない。

## 決定

- **変わらない部分を先に、変わる部分を後ろに並べる。** AI への依頼（`CompletionRequest`）に `context`（呼び出しをまたいで変わらない前提）を足し、`messages` には毎回変わる部分だけを入れる。並びは「指示 → 前提 → 変わる部分」に統一する
  - ヒアリング（生成AI・評価AI）: 前提 = プロジェクトの名前・目的・確定済みの要件。変わる部分 = フェーズ・質問・回答（評価AIは、それに評価する案を足す）。以前はフェーズが確定済みの要件より前にあったため、並びを変えた
  - 資料の分析: 前提 = プロジェクトと資料。変わる部分 = 特に見てほしい点・確定している要件。以前は見てほしい点が資料より前にあったため、観点を変えて分析し直すと長い資料を使い回せなかった
- **Claude（Anthropic）は、明示の印（`cache_control`）を2か所に付ける。** 指示の終わりと前提の終わり。指示は同じ種類の呼び出しなら、プロジェクトをまたいで使い回せる。回答や評価する案など毎回変わる部分には印を付けない（書き込みの割増 1.25倍だけがかかり、読み戻されないため）。保つ時間は `AI_CACHE_TTL`（既定 `5m`、`1h` も選べる。`1h` は書き込みが 2倍になるかわりに、回答の間隔が5分を超えても残る）
- **ChatGPT（OpenAI）・Gemini は、先頭が同じなら自動でキャッシュされる。** 並びをそろえるだけで効く。ChatGPT には、同じ指示・前提の呼び出しに同じ `prompt_cache_key`（指示と前提から作った短いハッシュ。中身は送らない）を付け、同じサーバーに寄せて当たりやすくする。互換サーバー（接続先を指定した場合）には、受け付けない項目かもしれないため送らない
- **ローカルLLM（Ollama）は、直前と先頭が同じ部分の計算結果を使い回す。** 並びをそろえ、モデルをメモリに残す時間（`keep_alive`）を 30分にする（既定の5分では、利用者が回答を考えている間に消えやすい）
- **利用量に「うちキャッシュ」を記録する。** `Usage.inputTokens` は、どの AI でも「キャッシュの分を含む入力の合計」にそろえ（Claude の `input_tokens` はキャッシュの分を含まないため足し直す）、そのうちキャッシュから読んだ分を `cachedInputTokens` として `usage_records.cached_input_tokens` に保存する。画面の「今月の利用量」に AI ごとの「うちキャッシュ」と割合を出す
- **月間トークン上限は、今までどおりキャッシュの分も含めた合計で数える。** 上限の意味（送ったトークンの量）を変えないため。料金の目安はキャッシュの割合から読み取る

## 対象外

- 評価AIと生成AIの間での使い回し。指示（system）が違い、指示は前提より前に来るため、同じ前提でも使い回せない。指示を前提の後ろに移すと AI への指示の効き方が変わるため、見送った
- UML・画面・タスク分解・非機能要件など、依頼の全文が前提にあたる呼び出しの前提部分の印。同じ依頼を5分以内に繰り返さない限り読み戻されず、書き込みの割増だけがかかるため、指示の部分だけをキャッシュする
- Gemini の明示のキャッシュ（cachedContents）と、ChatGPT の長期保持（`prompt_cache_retention`）。保存の料金や、使えるモデルの制限があるため
