# ADR 0010: 開発・テストのツールとは MCP・外部連携 API・開発用パッケージ・Webhook でつなぐ

- 状態: 決定
- 日付: 2026-10-03

## 背景

要件定義の成果物を、AIコーディングツール・CI・テストツールに渡し、実装状況とテスト結果を要件定義の側に戻したい。渡すだけで戻りがないと、要件どおりに作られたか・確かめられたかが要件ナビから見えず、推測で実装された箇所も分からない。

## 決定

- **AIコーディングツールには MCP サーバー（Streamable HTTP）を用意する。** Claude Code・Cursor・GitHub Copilot など主要なツールが対応しており、ツールごとの個別対応がいらない。セッションは持たず、応答は JSON で返す（サーバーからの通知は使わない）。MCP の SDK は使わず、必要な JSON-RPC のメソッド（initialize / ping / tools/list / tools/call）だけを実装する
- **MCP を使わないシステムには、同じ機能の REST API（/api/v1）と OpenAPI 3.1 の定義を用意する。** 内部では MCP と REST で同じ処理を使う
- **テスト結果は JUnit XML で受け取る。** ほぼすべてのテストツールが出力でき、テストツールごとの対応がいらない。テスト名に含まれるテストID・要件IDで結びつけるため、命名の決まり（AGENTS.md と Gherkin のタグ）を一緒に渡す
- **要件・設計・テストシナリオは、リポジトリに置けるファイル（開発用パッケージ）でも渡す。** AIツールは AGENTS.md を読む前提で作業の決まりを書き、Claude Code には CLAUDE.md から読み込ませる。テストシナリオは日本語のキーワードの Gherkin にする
- **AIツールが不明点を推測で埋めないよう、質問の経路を用意する。** 質問は着手前チェックの未決事項に出し、画面で回答する。要件の変更が必要なら変更管理に回す（質問から要件を直接書き換えない）
- **認証は組織ごとの API トークンにする。** 権限（参照／報告）・プロジェクト・有効期限（最長365日）で絞れる。SHA-256 だけを保存し、発行時に一度だけ表示する。トークンでは /api/v1 と /mcp 以外を使えない
- **外部への通知は Webhook（HMAC-SHA256 の署名つき）にする。** 送り先は https のみとし、社内アドレスへの送信は送るたびに名前解決して拒否する（SSRF 対策）。再送はせず、最後の送信結果を表示する

## 理由

- 要件定義の価値は、後工程で守られて初めて出る。実装状況とテスト結果を要件単位で戻せば、確定後の変更（ADR 0006）の影響も「報告後に要件が変わった」として見える
- 規格（MCP・OpenAPI・JUnit XML・Gherkin・HMAC 署名の Webhook）に寄せることで、特定のツールに縛られず、ツールが増えても対応がいらない
- 依存を増やさない（OSS 方針）ため、MCP・ZIP は最小限を自前で実装した。どちらも仕様の一部しか使わない

## 対象外・今後

- MCP のリソース・プロンプト、サーバーからの通知（SSE）、OAuth による認可は使わない（トークンで足りるため）
- Webhook の再送・配送履歴の保存はしない。必要になれば配送キューを追加する
- テスト管理ツール（TestRail・Xray など）への直接の登録はしない。CSV と API で取り込む
