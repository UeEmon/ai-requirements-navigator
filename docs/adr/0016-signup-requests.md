# ADR 0016: ログイン画面からの新規登録のリクエスト

- 状態: 決定
- 日付: 2026-11-12

## 背景

要件ナビのログイン（`AUTH_MODE=local`）では、アカウントは組織の管理者の招待でだけ作れる。使いたい人は、管理者を探してメールアドレスを伝え、招待してもらう必要があり、ログイン画面には「管理者に依頼してください」としか出ていなかった。一方で、誰でもアカウントを作れるようにすると、組織に知らない人が入る・AI のトークンを使われるおそれがある。

## 決定

- **自分で作るのではなく、リクエストにする。** ログイン画面の「新規登録をリクエスト」から、メールアドレス・名前・管理者への連絡（任意）を送る。リクエストだけではアカウントもパスワードもできない
- **承認は招待と同じ。** 組織の管理者（`member.manage`）が役割を選んで承認すると、その役割で招待し、パスワードを決める一回限りのリンクを発行する（招待の処理を共通にした）。要件ナビからはメールを送らない決まりのままなので、表示された文を管理者が本人に送る。見送りは本人に知らせない
- **届く組織はメールアドレスのドメインで決める。** 組織設定の「招待できるメールアドレスのドメイン」にそのドメインを入れている組織に届く。どこにもなければ、組織が1つだけでドメインを決めていないときに限りその組織に届く。組織の一覧は外に見せない（送る人に組織を選ばせない）
- **外から探れないようにする。** 届いたか・すでにメンバーかに関わらず同じ答え（202）を返す。未対応のリクエストは組織・メールアドレスで1件（送り直すと上書き）、1つの組織で100件まで
- **既定で受け付ける。** `LOCAL_SIGNUP_REQUESTS=off` で止められる。初期設定の前は受け付けない
- 保存先は `signup_requests`（マイグレーション 016）。リクエスト・承認・見送りは監査ログに残す

## 対象外

開発用ログイン（dev）とログイン画面（oidc。Cognito・Keycloak 側に新規登録の仕組みがある）。リクエストした人へのメール通知、承認時の自動送信（メール送信の仕組みは「次の候補」）。
