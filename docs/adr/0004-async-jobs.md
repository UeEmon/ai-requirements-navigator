# ADR 0004: AI処理は PostgreSQL のジョブ表で非同期に実行する

- 状態: 決定
- 日付: 2026-10-02

## 背景

複数AIの並列生成と評価には数十秒〜90秒かかる。1回のHTTP要求で待つと、ロードバランサーやブラウザの時間切れで結果を失うことがあり、画面も何が起きているか分からない。

## 決定

- 案の生成とUML生成は `?async=1` で受け付け、`202` とジョブIDを返す。画面は `GET /api/jobs/:id` で進み具合（AIごとの作成中／完了／失敗）と結果を取得する
- 待ち行列は PostgreSQL の `jobs` 表。取り出しは `FOR UPDATE SKIP LOCKED` で行い、AWS で複数のコンテナを動かしても1つのジョブは1回だけ実行される
- 実行中のまま止まったジョブ（コンテナの停止など）は、一定時間（AIの時間切れの5倍）で失敗にする
- 上限やフェーズの誤りは、受け付け時点で即座に返す
- 同期の呼び出し（`?async` なし）も残す（API利用やテストのため）

## 理由

- Redis などの追加の部品が不要で、ライセンス方針（ADR 0003 / OSS方針）とも合う
- ローカルDocker と AWS で同じ仕組みが動く

## 影響

- ジョブの結果は jobs 表に残る。必要に応じて古いジョブを削除する運用を追加する
